## Method

- **Live production walkthrough** in the owner's Chrome (Claude in Chrome), signed in, with QA TEST data only. Create, edit, confirm, connect, remove connection, search, review (duplicates, stale, unreachable), merge, contributor link (issue, use, renew, revoke), export, both languages.
- **Viewport and accessibility matrix.** The owner's Chrome is maximised (no resize) and the site CSP blocks injecting axe-core, so the production bundle was also loaded in local headless Chrome with a fake `aal2` session, the API replayed from the captured QA data, and CSP bypassed for axe only. That gave 16 screens × (Arabic at 375/768/1024/1280/1440, English at 375/1440) = 112 captures, plus axe-core 4.10 on 64 of them.
- **Stress pass** (same harness): 3-second API delay, API 500, network drop on save, 401 mid-session, invalid contributor link, duplicate hint on create, `prefers-reduced-motion`.

### Persona lock

**Owner on the go.** Runs the network alone (spec §1). Arabic-first, comfortable with tech, but uses the app in snatched moments: adds someone on the phone minutes after meeting them, often interrupted (a call, switching to WhatsApp to copy a number); searches and cleans up on a laptop. Wants the path to a person, not a database.

**Contributor with a link.** A friend doing the owner a favour on a phone, first visit, possibly on mobile data, no account, low patience. Will add a handful of people if it is effortless.

### Threads walked

1. Quick add after meeting someone (owner, `/add`): including real-flavour input and a double-click on Save.
2. Find someone for a need, see the path, contact them (`/search` → result → person).
3. Weekly cleanup (`/review/*`): duplicates, merge, needs confirming, not connected to you, round trip back.
4. Contributor adds people (`/links` → `/c`): issue, use, renew, revoke.
5. Backup (`/export`).

## What works well (with proof)

- [✓] **Idempotent create.** A double-click on Save sent exactly one `POST /people` (22:10:37).
- [✓] **Failed save keeps the input.** With the network dropped on save, the form says the input is saved on this device, and a reload restores it locked for retry (`evidence/offline-save-reload.png`).
- [✓] **Confirmation dialogs.** They name the person, state that the action can't be undone, put initial focus on Cancel, close on Escape and return focus (`evidence/live-delete-dialog.jpg`).
- [✓] **Round trips.** Remove connection → Review lists the person → Connect → the list empties without a reload. A new person appears in search immediately.
- [✓] **Arabic search folding.** أختبار finds اختبار; email duplicates are matched case-insensitively.
- [✓] **Contributor link security.** The token lives in the URL fragment and is stripped from the address bar. After renew, the old token returns `link_not_found`. An invalid link gets a clear "ask for a new one" message.
- [✓] **Session expiry.** Any 401 sends you to `/login` instead of leaving dead screens.
- [✓] **No hard-gate failures.** No horizontal page scroll or clipped text at any of the 5 widths; axe Critical/Serious = 0; CLS 0.

## Findings

### Critical

**C-1 Typed input is lost when the owner leaves the Add or Edit form or reloads it**
- Layer: Feedback. Surface: `/add`, `/people/:id/edit` (and `/c`), all viewports.
- Persona: Owner adding someone right after meeting them, interrupted by a call, or switching to WhatsApp to copy the number. Mobile browsers routinely discard background tabs.
- Reproduce: 1. Open `/add`. 2. Type both names, pick a strength. 3. Tap Search in the nav (or reload). 4. Press Back.
- Observed: The form is empty. No "unsaved changes" prompt.
- Expected: The typed values come back, editable.
- Evidence: `evidence/live-add-form-before-leaving.jpg` → `evidence/live-add-form-lost-after-back.jpg` (22:09:53).
- Suspected location: `apps/web/src/app/features/people/person-form.component.ts:781`. `saveDraft` runs only when a save fails; there's no draft on change.
- Smallest possible patch: In `ngOnInit`, add `this.form.valueChanges.pipe(debounceTime(400), takeUntilDestroyed(this.destroyRef)).subscribe(() => this.saveDraft(this.form.getRawValue(), null));`. Change `saveDraft(value, idempotencyKey: string | null)` so it stores no key when `null`. `loadDraft` already restores a key-less draft as editable and only locks drafts that carry a key. The existing `drafts.clear(...)` on successful save stays as it is.

### High

**H-1 Icons depend on Google Fonts; when that fails they render as text stubs**
- Layer: Visual. Surface: every screen. Seen live in the owner's own Chrome, where `fonts.googleapis.com` returned 503.
- Persona: Owner. The icon-only "remove connection" button shows as "lin", and chip and row remove buttons as "clos"/"de", during cleanup.
- Reproduce: Block `fonts.googleapis.com` (or open the site in the owner's Chrome profile) → open any person page.
- Observed: "sear", "pers", "fact", "lin", "dow", "lo" in place of icons (`evidence/live-person-ar-icons-as-text.jpg`).
- Expected: Icons render regardless of third-party availability.
- Suspected location: `apps/web/src/index.html:18-20`.
- Smallest possible patch: Download the Material Symbols Outlined woff2 (axes `opsz,wght,FILL,GRAD@24,400,0,0`) into `apps/web/public/fonts/`. Add an `@font-face { font-family: 'Material Symbols Outlined'; src: url('/fonts/material-symbols-outlined.woff2') format('woff2'); font-display: block; }` to `styles.scss` and delete the `index.html:20` link. Do the same for Readex Pro (line 18) if you want zero third-party font calls; CSP `font-src 'self'` would then suffice.

**H-2 When an i18n catalogue fails to load, the UI shows raw keys with no retry**
- Layer: Feedback. Surface: any screen on a first visit with no service worker yet, typically a contributor opening `/c` on mobile data.
- Persona: Contributor on a first visit, no account, low patience.
- Reproduce: Load any page with `/assets/i18n/ar.json` failing (seen during a network change in the matrix run).
- Observed: `pages.review.title`, `review.duplicates.keep`, `shell.signOut` and "…Name" in the header (`evidence/review-duplicates-ar-375.png`).
- Expected: Real Arabic text, or at least a retry.
- Suspected location: `apps/web/src/app/app.config.ts:30-31` (`provideTranslateHttpLoader`, with fallback `en` also loaded over HTTP).
- Smallest possible patch: Bundle both catalogues. Replace the HTTP loader with a static loader, `class StaticLoader implements TranslateLoader { getTranslation(l: string) { return of(l === 'ar' ? ar : en); } }`, importing `ar`/`en` from `@connections/i18n` (≈21 KB each, gzip ≈5 KB). Remove `/assets/i18n` from the service-worker asset group.

**H-3 The duplicate warning appears only after the duplicate has been created**
- Layer: Interaction. Surface: `/add` (and `/c`).
- Persona: Owner quick-adding someone who is already in the network (likely once contributors add overlapping friends).
- Reproduce: Add a person whose email or phone matches an existing record → Save.
- Observed: The second record is saved first, then "this person may already exist" appears; cleanup means a trip to Review → Merge (`evidence/duplicate-hint-on-create-after-save.png`).
- Expected: A warning before saving, with a "Open existing / Save anyway" choice.
- Suspected location: `apps/web/src/app/features/people/add-person.page.ts:107`; the API only returns `possible_duplicates` in the create response.
- Smallest possible patch: Add `POST /api/v1/duplicates/check` with body `{contacts, social_links}` → `DuplicateHint[]` (POST keeps contact values out of URLs), reusing the exact-match query behind `create_person`. In `person-form.component.ts`, call it on Save when contacts or links are present. If hints come back, show them inline with "Save anyway"; the second click submits.

**H-4 No "Add another person" after a normal save**
- Layer: Interaction. Surface: `/add` → person page.
- Persona: Owner adding three or four people met at the same event (the v0.1 success metric is 150+ people).
- Reproduce: Add a person with no duplicate → Save.
- Observed: The app lands on the new person's page; adding the next person means tapping Add in the nav again, and "Connected to" resets.
- Expected: "Add another person" available right after saving, as on the duplicate path and on `/c`.
- Suspected location: `apps/web/src/app/features/people/add-person.page.ts:110` (navigate) vs `:50` (`addAnother` only on the duplicate branch).
- Smallest possible patch: On a clean save, navigate with `{ state: { justAdded: true } }`. In `person.page.ts`, when `history.state.justAdded` is set, render a one-line banner "Saved. [Add another person]" linking to `/add` (reuse the i18n key `person.duplicates.addAnother`).

**H-5 Delete, Merge and Revoke look like ordinary actions**
- Layer: Visual. Surface: person page action row; merge dialog; delete dialog; Links.
- Persona: Owner tapping fast on a phone. "حذف" sits right beside "تأكيد أن البيانات ما زالت صحيحة" in the same outlined blue style.
- Reproduce: Open any person at 375px; open Review → Keep this one; open Delete.
- Observed: Delete is outlined blue like Edit/Confirm. The confirm buttons for Delete and Merge are filled primary blue, identical to Save. Revoke matches Renew (`evidence/person-A-ar-375.png`, `evidence/review-merge-dialog-ar-375.png`, `evidence/live-delete-dialog.jpg`).
- Expected: Destructive actions styled distinctly (error colour), and "can't be undone" stated up front.
- Suspected location: `apps/web/src/app/features/people/delete-person.dialog.ts:24`; the person page action row; the merge confirm in `features/review/duplicates.page.ts`; Revoke in `features/links/links.page.ts`.
- Smallest possible patch: Add a `.danger` class (`--mdc-filled-button-container-color: var(--mat-sys-error); --mdc-filled-button-label-text-color: var(--mat-sys-on-error)`, plus the outlined equivalents using `--mat-sys-error`) in `styles.scss`. Apply it to the four buttons, and move "Delete" to the end of the action row, after a spacer.

**H-6 On a phone, the path to the person is about 1,500px down the page**
- Layer: Architecture. Surface: `/people/:id` at < 720px.
- Persona: Owner who just found someone in search and wants to know "who introduces me".
- Reproduce: Open a person with skills, contacts and notes at 375px.
- Observed: "مسارك إلى هذا الشخص" (Your path to this person) and Connections come after seniority, availability, skills, industries, contacts, social links and private notes (`evidence/person-A-ar-375.png`).
- Expected: Path first; it is the product's reason to exist (spec §1).
- Suspected location: `apps/web/src/app/features/people/person.page.ts:117-177` (`.columns` grid, `.profile` before `.network`) and `:330`.
- Smallest possible patch: Add `@media (max-width: 719px) { .network { order: -1; } }` to the component styles. Grid items honour `order`, so the network section moves above the profile on phones only.

**H-7 Search silently caps results at 50**
- Layer: Feedback. Surface: `/search`.
- Persona: Owner running a broad query ("القاهرة", a skill category) once the network passes 50 matches.
- Reproduce: Search a criterion with more than 50 matches.
- Observed: "النتائج: 50" with no hint that more exist (`evidence/search-50-ar-375.png`: 50 cards, a 23,000px page on a phone).
- Expected: "Showing the 50 closest; narrow with a filter."
- Suspected location: `apps/web/src/app/features/search/search-query.ts:18` (`RESULT_LIMIT = 50`); `apps/api/src/connections_api/modules/search/router.py:45` (`le=50`).
- Smallest possible patch: When `results.length === RESULT_LIMIT`, render `search.limitReached` ("Showing the 50 closest people. Add a filter to narrow it down.") under the count. Add the key to `packages/i18n/{ar,en}.json`.

**H-8 Contributors need three taps before they can type a phone number**
- Layer: Interaction. Surface: `/c` at 375px.
- Persona: Contributor adding friends, where the phone or WhatsApp number is the one detail they know.
- Reproduce: Open a contributor link → find where to enter a number.
- Observed: More details → (scroll past 12 fields) → "Add a contact detail" → change the type from Phone. Nothing on the first screen invites a number (`evidence/contribute-ar-375.png`).
- Expected: One phone/WhatsApp field directly under the names.
- Suspected location: `apps/web/src/app/features/people/person-form.component.ts` (the contacts array starts empty and is rendered inside `<details>`).
- Smallest possible patch: When the form is created, push one contact row `{ kind: 'whatsapp', value: '' }`. Move the contacts block above `<details>` for the contributor variant (`draftKey` starts with `contribute`). Treat a blank value as "no contact" in the submit mapping so it isn't sent.

## Rejected after verification

- "Every 1024px Arabic capture is shifted sideways": a full-page capture artefact. Layout data shows `scrollWidth` = 1024 with 0 off-screen elements, and a viewport-only recapture renders correctly.
- "More details is open by default": the harness opened it deliberately.

- **Advanced polish (post-launch):** a pending-work count on the Review nav item; skeletons for the person page; an undo snackbar for "remove connection".

## Recommended guard rails

- **30-second dogfood drill** before calling any UI change done: open the page, type, primary action, watch 2s, open a related view, read the console.
- **Playwright killer flows** (CI, mocked API as in this audit's harness): Add → navigate away → back keeps input (C-1); double-click Save = one POST; Review unreachable → Connect → list empties; `/c` with the catalogue blocked still shows Arabic (H-2); person page at 375 shows the path above the fold (H-6).

## Hold this in your hands

This is a careful, honest object. Its dialogs name the person and tell the truth about what can't be undone. A dropped connection keeps your words, and the Arabic layout mirrors without the usual RTL scars. It feels built by someone who thought about failure. What it doesn't yet feel like is a pocket tool. The things the owner does standing in a hallway right after meeting someone get no help: the form forgets them when interrupted, a second entry needs another trip, the answer to "who introduces me" is buried under the profile, and the destructive buttons sit dressed like the safe ones. Fix those four and it goes from a well-made admin console to something you'd reach for without thinking.
