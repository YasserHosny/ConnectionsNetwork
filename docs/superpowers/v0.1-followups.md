# Connections Network v0.1: decisions and open follow-ups

This is the durable record of what was decided on the owner's behalf while building v0.1, and what is
still open. It replaces the build ledger (a git-ignored planning folder that is being deleted).
Open items below were checked against the code on `main` after PR #1 (the ledger's older "minor
(deferred)" lines that PR #1 fixed are not repeated). Items I could not confirm are marked
"(unverified)".

## 1. Decisions made on the owner's behalf

Each ruling says what it is and what it costs if the owner disagrees.

- R1: `SUPABASE_JWT_SECRET` is an optional setting, used only for the HS256 path (local and tests). Cost if wrong: one extra optional env var.
- R2: local DB tests run against a throwaway docker `postgres:17` (`scripts/test-db.sh`, port 54329) with Supabase stand-ins in `supabase/tests/standins.sql`, shared with CI. Cost if wrong: small script rework.
- R3: `upsert_tag(p_network_id, p_kind tag_kind, p_label, p_category skill_category)` takes the network explicitly (the contributor path has no network claim). Cost if wrong: one signature change.
- R4: SECURITY DEFINER functions rely on their owner bypassing RLS (`postgres` on hosted, as in ProcurePilot). Cost if wrong: contributor submissions fail on hosted until a policy or owner fix. Checked by deploy checklist steps 4 and 5.
- R5: pnpm 12.16.1 (`packageManager`) instead of the ProcurePilot pin 9.15.4, because it is what was installed. Cost if wrong: lockfile regeneration.
- R6: implementers did repo work only; the first deploy (bunny.net app, secrets, hosted migrations, restore drill) is owner-run. Cost if wrong: none, it is external and security-sensitive.
- R7: a 12-digit number `20xxxxxxxxxx` (the WhatsApp form) normalises to `+20...`, ahead of the plan's "10+ digits gets +20" rule. Cost if wrong: a rare national number starting 20 is mis-normalised.
- R8: Arabic-Indic and Extended Arabic-Indic digits are read as 0-9 in `normalize_phone`. Cost if wrong: none.
- R9: `normalize_email` returns NULL for blank input, so blank emails never collide in duplicate detection. Cost if wrong: none.
- R10: the claimed-profile connection rule (`person_a = me or person_b = me`) is deferred to v0.3, where claiming arrives. Cost if wrong: one extra policy in the v0.3 migration.
- R11: contributor functions are executable only by a NOLOGIN role `contributor_api` (never anon, authenticated, service_role or public), reached through `contributor_tx()`; the rate-limit key is domain-separated (`sha256("ratelimit:" + token)`), never the stored `token_hash`. Cost if wrong: a hosted grant step.
- R12: contributor endpoints have separate rate-limit buckets (30/min per link, 60/min per IP each for info, tags, people). Cost if wrong: 3x the per-link budget across endpoints.
- R13: keep the separate `apps/web` lockfile and the `--ignore-workspace` CI install (ProcurePilot pattern). Cost if wrong: two lockfiles to regenerate on web dependency changes.
- R14: a save that fails with `mfa_required` also saves the draft before going to `/mfa`, so typed input is not lost. Cost if wrong: one extra draft write.
- R15: the app initializer skips `AuthService.init()` on `/c`, so the contributor page never touches a Supabase session. Cost if wrong: an admin opening `/c` on their own device is not session-refreshed there (and in-app navigation from `/c` to an admin route lands on `/login`).
- R16: the nightly `/rest/v1/` keepalive tolerates 401, 403 and 404 (any HTTP answer); `/api/v1/health/db` is the real keepalive. Cost if wrong: a weaker keepalive signal.
- R17: tag alias management (spec section 7, "admin can mark a tag as an alias") is deferred to v0.2; autocomplete steers spellings in v0.1. Cost if wrong: the owner merges spellings with SQL until v0.2.
- R18: `Idempotency-Key` on `POST /people` and `POST /contribute/people`, with a per-submission web key kept in the draft. Cost if wrong: an extra table and code.
- R19: the API logs in as `connections_api` (NOLOGIN NOINHERIT NOBYPASSRLS, may only `set role` to `authenticated` and `contributor_api`); `postgres` stays for migrations, bootstrap and backup. Cost if wrong: one more deploy step (checklist step 4).
- R20: the optional photo (spec section 7) is deferred; `photo_path` is unused. Cost if wrong: the owner cannot attach photos yet.
- R21: "Send update link" stays, but its copy says honestly that the link lets the person add people and asks them to reply with changes to their own details (the admin edits), because `/c` cannot edit a profile. Cost if wrong: the owner may want a self-update step on `/c` later.

Later owner decisions (PR #1 review rounds):

- After a failed create the form is locked (option 1). Retry resends exactly what failed under the same key; "Start over" keeps the typed values editable under a fresh key and warns that a second save may add the person twice.
- The snapshot problem was fixed as a class, not per endpoint: export and every admin GET run in one REPEATABLE READ transaction (`admin_snapshot_tx`), with a guard test.
- A reused `Idempotency-Key` with a different payload answers 422 `idempotency_key_reused` (payload hash stored per key).
- A JWKS outage answers 503 `auth.keys_unavailable` instead of signing users out; stale refreshes honour a retry cooldown.
- Contributor drafts are owned by a SHA-256 digest of the link token (never the display name); drafts are cleared on sign-out; a save pending at sign-out or form destroy never writes its draft back (DraftStore generation).
- `_sync_contacts` keeps one row per contributor of a shared contact value, so editing a person does not erase another contributor's attribution.
- `ConnectDialog` closes when the session ends (401) or MFA lapses; Arabic uses one term for connection ("علاقة / علاقاته").

## 2. v0.2 backlog

- Fuzzy duplicate detection: similar names in the same script (`pg_trgm`), plus same city or profession, as weaker candidates in the duplicates list (spec 8.4). Thresholds are the builder's call.
- Needs log: who asked, the need, status (open / in progress / resolved / not resolved), people suggested (spec 8.9).
- "Need someone?" button on the contributor-link page (spec 8.2).
- Tag alias management: an endpoint and a screen for marking a tag as an alias (R17); until then merge spellings with SQL.
- Reconsider Supabase Pro when v0.2 starts (the Free plan has no backups; spec section 10).
- Optional photo (R20): private Storage bucket and `photo_path`.
- Self-update step on `/c` for an existing profile, only if the owner wants it (R21; spec 7.1 and 8.8 are ambiguous).

## 3. v0.3 backlog

- Member accounts and claiming a profile (spec 8.5); CSV import with column mapping (spec 8.10). Everything below depends on members existing.
- Claimed-profile connection rule: the profile's owner sees and edits connections others entered (R10).
- Merged-person visibility: with a single `created_by_person_id`, spec 7.2 ("any contributor who added that Person sees merged values") needs a rule.
- A collapsed edge keeps the keep-side creator: a member who created the drop-side edge loses it on merge (`merge_persons`).
- The owner of a claimed profile can reassign `created_by` and write any `added_by` on their own profile: needs a trigger.
- `person.admin_notes` is readable and writable by members: needs a column privilege or an admin-only table.
- Members cannot delete people (spec 7.2 lets the owner delete their own profile).
- Deleting a person cascades to the member row of a claimed profile.
- Existence leak: a foreign key to an unseen UUID reveals that the row exists.
- `member.user_id` is unique, so one account belongs to one network.
- Members' connection update and delete, and tag cross-network isolation, have no tests yet (unverified; only select and insert are covered in `test_member_visibility.py`).
- The auth hook role has `usage` on schema `public`; review when members arrive.

## 4. Still-open small findings

### Database and API

- `supabase/migrations/20261119000001_extensions_and_normalize.sql`:
  - `+20 (0)10...` (trunk zero after the country code) normalises to `+2001...`.
  - Scheme-relative URLs (`//host/x`) keep their slashes in `normalize_url`.
  - Unicode spaces other than U+00A0 are not collapsed.
  - `normalize_text` returns `''`, not NULL, for blank input.
- `tag` table: alias kind and alias cycles are not validated (only "not its own alias"); `person.available_for` accepts duplicate values.
- RLS accessors (`current_network_id`, `current_person_id`) raise on a malformed claim (still denies); `user_tx` opens a new connection per call.
- `apps/api/src/connections_api/shared/logging.py`:
  - `TraceIdMiddleware` trusts an incoming `X-Trace-Id` (no length or charset cap), and the 500 body's trace id may differ from the header.
  - The digit mask also masks UUID fragments and ISO dates.
- `apps/api/src/connections_api/db.py`: the `user_tx` docstring still says it switches to `anon` with no claims; that switch is unreachable for `connections_api`.
- `people/service.py` (516 lines) and `search/service.py` (348): split seams are tags, people, duplicates, connections.
- `_rows` helpers and the `Admin`/`Tx` aliases are copied across routers and services (search, review, duplicates, links, export, people).
- Input handling: NUL bytes in text fields give a 500 (reject in the shared string constraints); a blank connection note is stored as `""` not NULL; a diacritics-only tag label gives an empty `label_norm`. (unverified)
- Tag lookup: `/tags` suggestions resolve an alias one hop, `upsert_tag` and search follow up to 8.
- Search: a `q` that normalises to `''` is silently ignored when other filters are given.
- `merge_persons` repeats a `CASE` nine-fold (a `nonblank_or` helper would shrink it).
- Contributor payload: repeated social links are not collapsed (contacts are); payload limits are duplicated in `links/schemas.py` and SQL (commented); `ContributorPersonInput` may still advertise `admin_notes` in OpenAPI though it rejects it. (unverified)
- Export (`export/service.py`): generated and derived columns are exported; the owner's own profile can appear on the stale list. (unverified for the stale list)
- `apps/api/scripts/bootstrap_admin.py`: "already bootstrapped" is printed even when the existing member row is not an active admin; `load_dotenv` can leak a repo `.env` into later tests.
- Tests that prove less than their names say (all unverified): `test_usable_in_generated_columns_and_independent_of_session_settings`, `test_merge_is_one_transaction` (only refusal before writes), the lexicographic tie-break and cycle-path tests in `test_paths.py`, thin shadda and tanwin coverage, no Arabic-Indic digits with a `00` prefix, some cross-network FK tests that do not isolate one FK, untested alias chains of two or more hops, `test_contributor_api_role_is_narrow` checks direct members only (authenticator not covered).

### Infra, CI and ops

- `scripts/test-db.sh` exits silently (no message) when Postgres does not become ready within 60 seconds.
- `.github/workflows/ci.yml`: actions are tag-pinned (`actions/*@v4`, `astral-sh/setup-uv@v5`, `pnpm/action-setup@v4`); `gitleaks/gitleaks-action@v2` is unpinned and runs with a write-scoped `GITHUB_TOKEN`; no `ruff format --check`; the `lint:api` script in the root `package.json` is unused.
- `.github/workflows/deploy.yml` deploys on every push to `main` without waiting for CI.
- `infra/docker/api.Dockerfile` binds uvicorn to `0.0.0.0`; `docker-compose.yml` defaults `FORWARDED_ALLOW_IPS` to `172.16.0.0/12`, which misses `192.168.0.0/16`.
- `infra/nginx/security-headers.inc`: `style-src 'unsafe-inline'` is an accepted gap (Angular and Material set inline styles).
- `scripts/backup.sh`: the dump is checked only as non-empty and age-formatted (no minimum size); the `AccessKey` header is built with `printf '%s'` into a curl config line, so a key with a quote or backslash breaks it; `pg_dump` errors can print the pooler host and `postgres.<ref>` into the Actions log (private repo, so acceptable).
- `supabase/config.toml` (local only): password minimum 6 and `secure_password_change = false`; ports may collide with a ProcurePilot local stack (unverified). The hosted values are set by checklist step 7.
- `pnpm-workspace.yaml` comment points to `apps/web/pnpm-workspace.yaml`, which does not exist; `apps/web/eslint.config.js` still carries ProcurePilot comments (AGENTS.md, RequestsComponent).
- The test container `connections-test-db` is left running after `scripts/test-db.sh`.

### Web

- `apps/web/src/app/features/people/person-form.component.ts` is 865 lines (was 616 at review).
- After a locked Retry is refused for a data reason (for example 422 `person_not_found` because the "connected to" person was deleted), the user must press Start over, although nothing was stored under the key.
- Start over after a first attempt that did commit creates a duplicate person; the dialog warns about it and the duplicates review queue catches it (owner decision).
- Search page: no `maxlength=200` on `q`, `industry`, `city`; `aria-live` wraps the whole result list; search is capped at 50 with no paging; alternative paths use k=4.
- `contact-value.ts` flags year ranges such as `2020-2024` as contact-like (safe direction).
- Links page: renewing an active link silently invalidates the URL already sent (no hint or confirmation); creating a link for a deleted person shows the "connect" wording on 422 `person_not_found` (unverified).
- Unreachable page: after a connect, the person leaves the list even if the chosen peer is also unreachable.
- Person page: a PATCH or DELETE on a connection removed elsewhere (404) shows "person not found" with no refresh.
- Export page hint says a leading apostrophe is added to cells starting with `+`; phone-like cells are exempt (`_PHONE_LIKE`).
- A signed-in aal2 user who opens `/login` or `/mfa` stays there (`core/mfa.guard.ts` treats both as open).
- Static `<title>` in `apps/web/src/index.html` (no per-page titles); the language switch `aria-label` has no `lang`.
- `ApiClient` fallback messages are English (`core/api.client.ts`); pages map by error code, but not every page was re-checked. (unverified)
- No automated check for literal template strings in i18n; no console-silence assertion on the contributor page; the ignored promise of the same-route `navigateByUrl` in `contribute.page.ts`.
- `person-form` saves `output<unknown>` and casts; `mat-radio` has a test-only `[attr.value]`. (unverified)

## 5. Hosted-deploy checks to remember

The first deploy ran on 2026-11-24 and 2026-11-25 (`https://connections.iron-sys.com`). Items
marked **Done** were confirmed then; everything else is still open. Every item is the owner's, and
`docs/operations/deploy-checklist.md` has the commands.

- Migrations: apply all nine through the session pooler only; `pg_trgm` must be in `public` before migration 1 (it refuses otherwise); `select public.similarity('ahmed','ahmad')` must answer.
- Data API off (step 3): remove `public` and `graphql_public` from exposed schemas, disable `pg_graphql`; `curl <ref>.supabase.co/rest/v1/person` must not return 200. `supabase/config.toml` sets `[api] enabled = false`, but that was never run with `supabase start`.
- `connections_api` (step 4): `alter role ... login password`; check `pg_has_role('connections_api', 'authenticated' | 'contributor_api', 'SET')` is true, no other role can become `contributor_api` (anon, authenticated, service_role, authenticator), and `select count(*) from public.person` is refused as `connections_api`. Migration 9 needs hosted `postgres` to hold ADMIN on `authenticated`; if the grant fails, check that first. Supavisor accepting `connections_api.<ref>` is assumed, not tested.
- `contributor_api` and `connections_api` roles exist and the contributor submission smoke test passes on hosted (R4, R11, R19); `set role contributor_api` by a non-superuser login was never tested locally.
- SECURITY DEFINER owners must be `postgres` with `rolbypassrls` (step 5); the admin token must carry `network_id`, `member_role`, `person_id`, and `aal2` after TOTP.
- No excess privileges for `anon` and `authenticated` (step 6 queries must return no rows).
- Tag autocomplete smoke on hosted: `GET /api/v1/tags` and `GET /api/v1/contribute/tags?kind=skill&q=a` (the `kind` parameter is required).
- Auth settings (step 7): sign-ups off, TOTP on, password minimum 12, secure password change on, access-token hook set to `public.custom_access_token_hook`, Site URL and Redirect URLs set to the public origin only.
- **Done (2026-11-25, build `3ff4c02`, PR #5):** real client IP behind bunny.net.
